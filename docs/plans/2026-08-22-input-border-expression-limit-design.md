# 입력 보더 복원 및 표정 이미지 제한 설계

## 목표와 사용자 경험

입력 계열 컨트롤의 기본 보더를 접근성 보강 전 색상인 `#444b56`으로 되돌린다. 버튼, 모달, 포커스 링은 현재 대비가 높은 스타일을 유지하므로 키보드 포커스 표시는 계속 분명하다. 검색 입력의 외곽 래퍼도 일반 입력과 같은 보더를 사용한다. 이 선택은 어두운 입력 배경 `#151920`과의 대비가 약 `2.0:1`이어서 WCAG 2.2 1.4.11의 3:1 기준을 충족하지 못한다. 자동 검증은 이 사실을 숨기지 않고 기존 색상과 알려진 미달을 확인하며, 자체 검수 문서에는 의도적 예외로 기록한다.

COC와 InSane의 `표정별 이미지`는 각각 최대 6개만 보유한다. 화면에서는 현재 개수와 최대 개수를 항상 보여주고, 6개가 되면 추가 버튼을 비활성화한다. 추가 핸들러도 길이를 검사해 중복 이벤트나 프로그램 호출로 7번째 항목이 생기지 않게 한다. 저장 JSON·로컬 저장값·가져오기 데이터가 6개를 초과하면 유효한 항목 중 앞의 6개만 유지한다. 이렇게 하면 UI만 제한하고 데이터 경로로 우회되는 불일치를 막을 수 있다.

## 구조와 검증

공용 `MAX_STANDING_IMAGES = 6` 상수를 별도 모듈에 두고 COC 정규화, InSane 정규화, 두 UI가 함께 사용한다. COC는 문자열 쌍인 항목을 순서대로 최대 6개 보존한다. InSane은 기존처럼 라벨과 URL이 모두 유효한 항목만 보존한 뒤 6개에서 자르고, 이전 `extraImageUrls` 호환 경로도 같은 제한을 적용한다.

TDD로 정규화의 7번째 항목 절단, COC/InSane UI의 6회 추가와 7번째 차단, 버튼의 비활성 상태와 안내 문구를 먼저 실패시킨다. 브라우저 테스트는 기존 보더 색상, 남아 있는 버튼 대비, placeholder 대비와 포커스 링을 확인한다. 완료 후 Vitest, TypeScript, 프로덕션 빌드, Playwright 세 viewport를 모두 실행하고 `dev`와 `main`을 동일 SHA로 맞춘 뒤 `gh-pages`를 재배포한다.
